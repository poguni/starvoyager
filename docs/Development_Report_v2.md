## 2. 목표 및 배경

교과서는 천체 관측 앱·검색 활동으로 태양계와 별자리를 다루지만, 학생이 행성의 크기·표면·고리, 별의 움직임을 **직접 보고 조작하며** 이해하기는 어렵다. 별빛 탐사선은 이를 하나의 '탐사' 경험으로 묶는다.

- **핵심 가치:** 실제 사진 질감으로 만든 3D 태양계와 실제 별 자료로 그린 밤하늘에서, '예측 → 확인 → 최종 답 → 한 줄 정리' 미션으로 교과서 개념을 스스로 확인한다.
- **교실 운영:** 교사가 전자칠판으로 시연(`?mode=demo`) → 학생이 크롬북으로 개별 탐사 → 전자칠판에서 학생 도감 발표. 결과는 교사의 구글 시트에 자동으로 쌓인다.
- **품질 원칙:** 전자칠판에서 실감 나는 3D를 우선하되, 행성이 9개라 가까이 간 천체만 고해상도 질감을 불러오는 구조로 처음부터 설계했다.

## 3. 주요 기능

| 탐사 | 내용 | 주요 장면·기능 |
|---|---|---|
| 탐사 1 | 태양계 구성원과 태양 | 태양계 지도(태양·행성 8개·달·혜성·소행성 띠), 구성원 찾기, 태양 빛 가리기, 공전 재생, 요일 카드 |
| 탐사 2 | 행성 탐사와 도감 | 행성 가까이 보기(1K→4K 질감), 고리 찾기 돋보기, 착륙(단단한 땅/기체)과 착륙 뒤 둘러보기, 탐사 도감 8장, 발표 화면, 행성 랩 만들기(C-1) |
| 탐사 3 | 크기 비교 실험실 | 실제 크기 비율, 줄 세우기, 나누어 담기, 태양과 비교 |
| 탐사 4 | 북쪽 밤하늘 별자리 | 서울 북쪽 하늘(실제 별), 시각 슬라이더, 별 잇기 3개(북두칠성·카시오페이아자리·작은곰자리), 주변 불빛, 새 별자리 이름(C-2) |

공통 기능:
- 탐사 대원 등록(S01) → 탐사 선택(S02, 순서 잠금 없음) → 탐사별 진행 저장·이어서 하기
- 흥미 체크(흥미1~5), 결과 행을 구글 시트 '미션'·'도감' 두 탭으로 전송, 인터넷이 끊기면 대기열에 두었다가 다시 보내기
- 혜성·소행성 소개 카드, 브라우저 뒤로 가기 → 탐사 선택 화면
- 시연 모드(`?mode=demo`): 등록·전송·기기 저장 없음, 큰 글씨, 이름 라벨 숨김
- URL 파라미터로 시작 장면 고정(`?mission`, `?view`, `?planet`, `?time` 등), 차시별 QR

## 4. 기술 스택 및 아키텍처

| 구성 요소 | 사용 | 선택 이유 |
|---|---|---|
| 빌드 | Vite 8 (`base: '/starvoyager/'`) | 달빛 관측소 파이프라인 재사용, GitHub Pages 프로젝트 경로 |
| 언어 | 순수 JavaScript(ESM) | 프레임워크 없이 유지보수, 달빛 관측소와 같은 구조 |
| 3D | three ^0.186 (OrbitControls, EffectComposer + UnrealBloomPass) | 질감·조명·후처리 |
| 북쪽 밤하늘 | 2D Canvas, 입체 사영 | 가로 시야 100°가 넘어 원근 3D는 가장자리 별자리가 늘어남, 크롬북 부담도 적음 |
| 테스트 | Vitest 5 | 판정·계산 순수 모듈 검사(15개 파일, 255개) |
| 결과 저장 | Google Apps Script 웹앱 → 구글 시트 두 탭 | 교사 계정 시트로 바로, 대시보드 없이 시트에서 확인 |
| 배포 | GitHub Actions → GitHub Pages (Node 22) | push하면 테스트 → 빌드 → 배포 |
| 글꼴 | Pretendard(한글 2,350자 하위 집합), IBM Plex Mono | 외부 CDN 없이, 약 2MB → 510KB |
| 자료 | Solar System Scope 질감(CC BY 4.0), NASA 질감, 예일 밝은 별 목록 | 실사 품질, 저작권 정리 |

### 4-1. 폴더 구조

```
src/
├─ main.js         장면·UI·미션·제출을 잇는 진입점
├─ data/           별·별자리·도감 정답·랩 조각·고정 날짜·혜성/소행성 소개
├─ model/          순수 계산(궤도, 크기 비교, 별 위치, 별 잇기, 도감, 진행 저장 …)
├─ missions/       engine.js(미션 상태 기계), missions.js(탐사 1~4 문항)
├─ scene/          태양계 지도·카메라·질감 단계·재질·고리·블룸·착륙·크기 비교·밤하늘
├─ ui/             HUD·이름표·도감·발표·미션 패널·끌어다 놓기·등록·탐사 선택·소개 카드
├─ student/        학생 정보 검증·저장
├─ submit/         시트 제출·대기열
├─ styles/         tokens.css(디자인 토큰), components.css, app.css
└─ debug/          FPS 측정기, 부품 견본
```

### 4-2. 화면 층

```
#app
 ├─ 3D 캔버스         태양계 지도·행성 탐사·착륙·크기 비교(한 renderer를 장면들이 나눠 씀)
 ├─ 밤하늘 층          2D 캔버스 + 별 누르기 칸 + 별자리 문장
 ├─ HUD               네 모서리 꺾쇠, 상단 계기판, 하단 조작 버튼
 ├─ 이름표 · 소개 카드
 ├─ 오른쪽 패널        도감(종이) / 미션(어두운 유리). 크롬북 크기에서 도감은 아래 패널
 ├─ 줄 세우기 판 · 발표 화면
 └─ 등록·탐사 선택 화면(보이는 동안 3D를 그리지 않음)
```

### 4-3. 핵심 구조

- **계산과 화면 분리:** 판정·계산은 DOM·Three.js 없이 `model/`, `missions/`, `data/`의 순수 모듈로 만들고 Vitest로 검사한다. `scene/`은 그리기만, `ui/`는 DOM만 만들고 `main.js`가 잇는다.
- **질감 단계 불러오기:** 처음에는 모든 천체가 1K. 가까이 간 천체와 그 이전·다음 천체만 4K(`?quality=low`면 2K)로 바꾸고, 멀어지면 30초 뒤 1K로 되돌려 메모리에서 해제한다.
- **미션 엔진:** 탐사를 단계 목록으로 보고 상태 기계로 진행한다.

```
intro / gate(찾은 개수 조건) → quiz: predict → (오답) confirm → result
→ sort·classify: arrange → result → summary → summaryResult → feel
→ creative → creativeResult → survey → done
```

- **저장:** localStorage 네 키(학생 정보, 도감, 탐사 진행, 제출 대기열). 시연 모드는 아무것도 저장·전송하지 않는다.
- **제출:** 한 기기에서 한 행씩 차례로 보내고, 실패하면 대기열에 두어 온라인 복귀·탐사 선택 화면 열기·'다시 보내기'에서 다시 보낸다.

## 6. 주요 의사결정과 이유

전체 77건은 `docs/결정기록.md`, 겉모습은 `design/README.md`의 '디자인과 다르게 정한 것' 표에 있다. 중요한 것만 묶었다.

| 결정 | 이유 |
|---|---|
| 북쪽 밤하늘은 3D가 아닌 2D 입체 사영 | 두 별자리를 한 화면에 담으면 원근 3D 가장자리 모양이 늘어나고, 크롬북 부담이 큼 |
| 밤하늘 날짜는 3월 12일로 고정 | 저녁 6시~아침 6시 내내 북두칠성·카시오페이아자리의 모든 별이 지평선 위(9월 7일 후보는 새벽에 알카이드가 짐) |
| 크기 비교는 정사영 카메라 | 원근 왜곡 없이 화면 속 크기가 15장 비율과 정확히 같게 |
| 태양계 지도 표시 크기는 모형이지만 크기 순서는 실제와 같게 | 지도에서 순서가 뒤집혀 보이면 탐사 3에서 오개념 |
| 이전/다음 행성은 행성 8개만 돎 | 문항 1-4 확인 방법에서 태양까지 9개로 세지 않도록 |
| 예측 단계에서 확인 도구·이름 보기 잠금 | '미션이 허용한 조작만'을 구체화, 답이 미리 드러나지 않게 |
| 힌트가 없는 문항은 새 힌트를 만들지 않고 '확인 방법'을 해요체로 | 학생용 문구를 임의로 만들지 않는다는 원칙 |
| 흥미 체크 값은 흥미1~5 | 기획서 허용 목록(1~4)과 탐사 4 문항 수(2개)가 맞지 않았음 |
| 제출은 한 행씩 차례로 | 동시에 보내면 Apps Script가 응답 단계에서 404를 자주 돌려줌 |
| 웹앱 주소는 Secrets가 아닌 Variables | `VITE_` 값은 빌드된 JS에 그대로 들어가 원래 비밀이 아님. 보호는 `Code.gs` 입력값 검증이 함 |
| 시연 모드는 기기 저장도 안 함 | 교사 기기에서 학생 기록과 섞이지 않게 |
| 혜성·소행성 소개에 '태양 주위를 돌아요'를 쓰지 않음 | 문항 1-2('태양의 주위를 도는 천체' = 행성)와 헷갈리지 않게 |
| 뒤로 가기는 방문 기록 한 칸(주소 그대로)으로 처리 | 한 페이지 앱이라 방문 기록이 하나뿐이어서 탭이 닫혔음 |

## 7. 문제 해결 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| 동시에 다시 보내면 같은 행이 두 번 감, 보내는 중 실패한 행이 사라짐 | 다시 보내기가 겹쳐 실행되고, 대기열을 통째로 덮어씀 | 다시 보내기 겹침 방지, 보내는 동안 새로 쌓인 행은 남김(테스트 추가) |
| 여러 행을 한꺼번에 보내면 절반쯤 404 | Apps Script 응답 단계 문제 | 한 기기에서 한 행씩 차례로 전송 |
| 시연 모드에 '다른 친구가 사용해요' 버튼이 보임 | 버튼 스타일의 `display`가 `hidden` 속성을 덮음 | `[hidden]` 규칙 추가 |
| 태양 절반에 줄무늬 | 일렁임 효과가 질감을 옆으로 흘리는데 가로 반복 설정이 없어, 시간이 지날수록 끝 한 줄이 늘어남 | 태양 질감 가로 반복, 흐름 값 `fract` |
| 크롬북에서 '태양과 비교하기' 때 행성·태양이 사라짐 | 미션 패널 옆 폭(약 840px)에 이름 자리 84px × 8이 넘쳐 크기 계산이 0 | 폭이 좁을 때만 이름 자리를 필요한 만큼 줄임(테스트 2개) |
| 착륙 뒤 손을 떼도 마우스만 움직이면 시점이 돎 | 누르기 상태를 손을 뗄 때 비우지 않음 | 손을 떼면 늘 비움 |
| 탐사 3 뒤 탐사 4에서 밤하늘 위에 행성 줄이 보임 | three.js가 3D 캔버스에 인라인 `display:block`을 넣어 `hidden`이 듣지 않음 | 캔버스를 만든 뒤 인라인 display 제거 |
| 탐사 3 뒤 밤하늘에서 '이름 보기'에 행성 이름이 함께 보임 | '이름 보기'가 크기 비교 이름표도 늘 함께 켬 | 실험실 안에서만 켬 |
| 탐사 중 뒤로 가기에 탭이 닫힘 | 한 페이지 앱이라 방문 기록에 앱 항목이 하나뿐 | 장면에 들어갈 때 방문 기록 한 칸, 뒤로 가기 → 탐사 선택 |
| 실제 시트 점검 스크립트의 요청이 모두 실패 | 앞 Playwright 스크립트의 `page.route` 차단이 남아 있었음 | `unrouteAll` |

## 8. 보안/성능 고려사항

**보안·개인정보**
- 학생 이름은 시트로 보내는 요청 본문에만 들어가고, 콘솔·오류 메시지·디버그 패널에는 남기지 않는다(Phase마다 콘솔에 이름 0줄 확인).
- 웹앱 주소는 `.env`(git 제외)와 저장소 Variables로만 넣는다. 시트 쪽 `Code.gs`가 학년 1~6·반 1~20·번호 1~40·이름 1~10글자, 문항 ID·행성 이름 허용 목록으로 검증하고 `LockService`로 동시 쓰기를 직렬화한다.
- 앱 본체는 외부 CDN을 쓰지 않는다. 인터넷은 결과 제출 때만 쓴다.

**성능**
- 질감 단계 불러오기(지도 1K, 가까이 간 천체만 4K), 화면 배율 제한(기본 2, low 1.5), 블룸은 `?fx=off`·`?quality=low`에서 끔
- 행성 탐사·발표 화면에서는 다른 천체·궤도선을 감추고, 등록·탐사 선택 화면에서는 3D를 그리지 않음
- 번들: JS 767KB(gzip 214KB) 중 three.js 약 596KB, 앱 코드 약 171KB. Vite 500KB 경고는 고치지 않고 선택지만 정리(v1 10-4)
- `?debug=fps`로 장면별 FPS 측정, 측정표는 `TEST.md`

## 11. 알려진 한계

- **기기 간 이어 하기 없음:** 진행 상태는 그 기기의 브라우저에만 있다. 차시마다 크롬북이 바뀌면 이어지지 않는다(기획서 16장 3번).
- **시트 중복 행 가능성:** Apps Script가 이미 적은 행에 404를 돌려주면 다시 보낼 때 같은 행이 한 번 더 쌓일 수 있다(재제출 허용과 같은 취급).
- **실제 크기 비율의 한계:** 태양과 비교할 때 수성~화성은 화면에서 점처럼 작다(실제 비율이라 의도된 모습).
- **착륙 장면은 연출:** 땅은 행성 질감 색으로 코드로 그린 것이라 실제 탐사 사진과 다르다.
- **밤하늘 날짜 고정:** 실제 수업하는 날의 하늘과 별자리 위치가 다를 수 있다.
- **번들 크기 경고:** 그대로 둠.
